# GPUI UI Library Parity

Native SDK exposes a machine-checkable counterpart for every public module in
two pinned GPUI ecosystem catalogs:

- Zed `crates/ui`: 42 modules at
  `6bf539cd52126974eb0dbff667de02a696a737ec`
- `gpui-component` `crates/ui`: 57 modules at
  `334bbed2e8c47d606eb79ab05ddcebd60b823429`

The source of truth is `native_sdk.canvas.ui_library`. Each entry records the
reference source and module, its Native SDK entry point, and the implementation
class. A generated receipt binds each inventory to its authoritative source
path, Git revision, and SHA-256. Tests compare the registry in both directions
with that receipt, reject duplicates, and reflect every `Ui.*` or `canvas.*`
entry back to a real public declaration.

```zig
const native_sdk = @import("native_sdk");
const catalog = native_sdk.canvas.ui_library;

comptime {
    if (catalog.count(.zed_ui) != 42) @compileError("Zed UI catalog drift");
    if (catalog.count(.gpui_component) != 57) @compileError("gpui-component catalog drift");
}
```

## What parity means

The catalogs describe more than leaf controls. They include composites,
editor/data surfaces, layout algorithms, platform services, and state managers.
Native SDK maps each one to the narrowest honest owner:

There is no `missing` class and no placeholder implementation.

## Named builder surface

Every retained widget now has a named constructor; callers no longer need
`Ui.el` just to reach data grids, tables, popovers, menu surfaces, icon buttons,
segmented controls, or the complete form-control set.

Reference-library names that are compositions are public too:

```zig
const Ui = native_sdk.canvas.Ui(Msg);

fn commandPalette(ui: *Ui, model: Model) Ui.Node {
    const search = ui.searchField(.{
        .text = model.query,
        .on_input = Ui.inputMsg(.query_changed),
        .semantics = .{ .label = "Search commands" },
    });
    const results = ui.list(.{}, commandRows(ui, model));

    return ui.commandPalette(.{
        .on_dismiss = .close_commands,
        .semantics = .{ .label = "Command palette" },
    }, search, results);
}
```

The builder does not own `query`, selection, open state, history, Dock layout,
form validation, or notification lifetime. Those values remain in the caller's
model and are passed into the view on every build.

`Ui.hoverCard` follows the same rule. It binds hover-enter and hover-leave
messages to both the trigger and the open card, while the caller owns intent,
delay timers, and the `open` flag. A closed build contains only the trigger; an
open build adds an anchored popover, without creating component-local state.

Markup uses the same foundations. Direct controls keep their existing element
names; semantic composites can be written as ordinary templates and `<use>`
calls, preserving the same structural identity as their expanded widget tree.
See [Building Components](/docs/building-components).

## Runtime boundary

This parity layer does not embed GPUI and does not copy `App`, `Context`,
`Entity`, `Global`, `Window`, executor, focus, input/IME, accessibility, or
platform lifecycle ownership. Ordinary UI remains Native markup and retained
canvas widgets; high-frequency editor, terminal, media, chart, and virtualized
content reuse the existing bounded surfaces.

UI-library API parity is also not a claim that every platform backend is at the
same maturity. Backend accessibility, complex text shaping, fractional scaling,
and real-host conformance remain tracked by [Platform Support](/docs/platform-support).
